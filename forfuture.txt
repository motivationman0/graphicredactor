# Архитектура 2D CAD проекта

## 1. Золотое правило проекта
Ввод и Вывод абсолютно изолированы друг от друга. Они ничего не знают о существовании друг друга и общаются исключительно через посредника — Блок хранения (Canvas).

## 2. Карта модулей (Файлы)

### 📦 Canvas (canvas.h / canvas.cpp)
* **Роль:** Блок хранения данных (Модель / Единый источник правды).
* **Что внутри:** Только чистые структуры данных C++ (координаты, геометрия, примитивы, цвета в RGB) и математические алгоритмы (поиск пересечений, Quadtree).
* **⚠️ ЖЕСТКОЕ ПРАВИЛО:** Никакого SFML или других графических API внутри этого модуля. Файл должен оставаться "невесомым" для компиляции и легко тестироваться чистой математикой.

### 🎮 InputHandler (inputhandler.h / inputhandler.cpp)
* **Роль:** Блок ввода (Контроллер).
* **Что внутри:** Перехватывает сырые системные события (в нашем случае `sf::Event` из SFML), переводит их на язык логики приложения и вызывает соответствующие методы изменения данных в классе `Canvas`.

### 🖥️ Render (render.h / render.cpp)
* **Роль:** Блок вывода (Представление / Рендерер).
* **Что внутри:** Единственное место, куда легально подключаются тяжелые графические библиотеки (SFML/OpenGL). Он заглядывает в чистый `Canvas`, считывает координаты объектов и физически отрисовывает их пиксели на экране (`sf::RenderWindow`).

### ⚙️ Main (main.cpp)
* **Роль:** Точка входа и "клей" приложения.
* **Что внутри:** Лаконичный код (около 30 строк). Инициализирует окно SFML, создает по одному экземпляру классов `Canvas`, `InputHandler`, `Render`, связывает их ссылками и крутит главный цикл (события ввода -> отрисовка кадра).

## 3. Инженерные паттерны на будущее

* **Опережающее объявление (Forward Declaration):** В `.h` файлах пишем `class Canvas;` вместо тяжелого `#include "canvas.h"`. Сам инклюд пишем только в `.cpp`. Это защищает от циклической зависимости и ускоряет сборку.
* **Паттерн "Команда" (Command) для Undo/Redo:** Блок ввода не меняет Canvas напрямую, а создает объект-команду с методами `execute()` и `undo()`. Команды складываются в два стека в памяти.
* **Quadtree (Четверичное дерево):** Пространственный индекс внутри Canvas. Делит экран на квадранты, чтобы программа не перебирала тысячи объектов циклом, а мгновенно находила фигуру под курсором мыши.
* **Динамическая линковка (.DLL):** Не вшиваем SFML намертво в `.exe`. Оставляем его внешним сменным блоком, который Windows подгрузит в RAM при старте.
